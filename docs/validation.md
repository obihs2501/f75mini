# 验收说明

## 当前边界

本版是**只读预览**，不是 PRD 的 P0 真机写入验收版。GitHub runner 没有 F75；自动测试通过不能证明硬件通路兼容。读请求可能通过发送 HID 查询报文完成；这不等于有设备配置写入的入口。蓝牙、F75 Wired 独立机型、Max / HE、区域布局均不作为已验证目标。

| 项目 | USB-C 候选 `258A:010C` | 2.4G 候选 `3554:FA09` |
|---|---|---|
| 设备枚举、型号线索 | 已有接口筛选；待真机 | 已有接口筛选；接收器存在不代表键盘已响应；待真机 |
| 灯光、系统模式、休眠、基础矩阵 | 只读，满足返回校验才展示；待真机 | 只读能力以实际已实现和返回校验为准；待真机 |
| 电量 | 当前无有线百分比读数 | 有依据的查询、按供电状态判定；待真机 |
| Win 固件锁 | 手册指引，软件无法读取或修改 | 同左 |
| 灯光及键位写入、宏、档位、逐键 RGB、实时灯效、软件重置 | 未开放 | 未开放 |
| 存储格式 | 部分配置快照 JSON，不可恢复到设备；演示文件与真机隔离 | 同左 |

### HID 读路径

- 有线：核对 Feature 报告 `06` 与 520 字节描述符；通过 `82` 查询型号、`84` 查询灯块、`83` 查询基础键位矩阵。无线：核对输入/输出报告 `13` 与 20 字节描述符；通过 `05` 查询型号、`44` 查询灯块、`41` 查询基础键位矩阵、`4A` 查询电量。分别校验回显或分包和校验和。
- 读取型号后要求协议型号字节 `CD`，但这个值不能识别 ANSI/ISO 布局或证明固件写入安全；不检查可被用户修改的 Esc 映射来推断身份。
- 参考 [F75 Studio 协议](https://github.com/trenbolone1122/aula-f75-linux/blob/4f7cebe04ad6a70345e7d1df72c1ce17786c14c4/docs/PROTOCOL.md)、[Remap75 协议实现](https://github.com/rosman21/aula75-remapper/blob/853f7e10f03977740eb7b2f2d465842813cac12e/data/src/protocol.rs) 和 [sanshoku 电量实现](https://github.com/ushineko/sanshoku/blob/b23c1bb65fd43bc0af1d306a6f20f78ab5f968ea/aula/decode.go)。遇到布局、回显或分包差异，本版宁可不展示读数；待真机确认能否覆盖更多固件。

## 无硬件测试（GitHub Actions）

- C++ 模型：ANSI 键数与布局、演示文件往返、格式和范围检查、不覆盖语义、异常数据拒绝、只读快照导出及隐私。
- CLI：帮助、候选设备 JSON、演示文件创建与验证、错误退出码、拒绝未开放的恢复命令。
- GUI：启动与正常关闭（不读取、修改真实设备）。

## 真机验证清单（尚未验收）

1. 记录型号、变体、接线方式、底行照片、硬件及固件可读取标识；逐条通路验证，不能从有线推导无线。以只读查询开始，不凭 VID/PID 或某个用户可改键位确认布局。
2. 有线直连验证识别和读数；无线先让接收器在线、键盘关机或休眠，核对未响应提示，再唤醒。模拟设备占用、拔插及多设备；核对读取中断时界面仍可交互且旧快照不能导出为当前状态。
3. 确认模式切换后刷新结果，核对基础矩阵和左 Win 的实际位置；验证 Fn+Win 只作为对应手册的 Windows 模式指引，不将映射恢复当作解除固件锁。无线应区分电池供电与外部供电的百分比。
4. 正常版在有明确变体及布局证据、正反协议测试、低风险写入/读回/断电保持实测之前，不放行硬件写入。断电保持与即时读回分别记录；宏和实时灯效逐能力验收。
5. Windows 10 / 11 上人工验证 960 × 640、1180 × 760、125–200% 缩放、键盘导航、浅深色及辅助技术。发布前记录可执行文件体积、冷启动和空闲内存，而不是把 CI 服务端测试视为桌面性能验收。

上游资料及可适用的证据分级见 PRD 第 10 节。兼容性未知不等于硬件不支持。提交读数问题时，请附上连接方式、底行布局和程序给出的错误状态；请勿上传含有个人自定义映射的文件，除非已自行审阅内容。
